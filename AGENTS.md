# Working in FireShield

## Project context

This is the user's Amazon Build, Ship, Shape hackathon repository. Fire TV is the intended primary track. The user's prior research document has not yet been supplied in this repository, and the product direction and stack are not finalized.

## Working rules

- Respond and write project documentation in English.
- Read README.md and the relevant research and validation documents before selecting implementation work.
- Preserve researched constraints and source attribution when importing the user's document. Record contradictions and open questions explicitly.
- Do not infer a security product from the name FireShield.
- Distinguish source-backed facts, inferences, hypotheses, and actual experiment results.
- Evaluate business demand and technical feasibility alongside originality.
- Check current official documentation for platform capabilities and hackathon requirements before relying on them.
- Preserve third-party licenses and attribution. Do not copy code with unclear reuse terms into the project.
- Never commit credentials, tokens, personal customer information, or private interview transcripts. Use anonymized summaries.
- Use small, reviewable commits. Read the latest branch head before updating it and do not overwrite concurrent work.
- Test executable changes with checks appropriate to their behavior. Document the environment, commands, and material limitations; do not label an unrun check as passing.
- Add setup and run instructions when application code is introduced.
- The current repository setup does not configure continuous background execution.
