## Platform and implementation

- [ ] Select Fire OS or Vega OS based on the actual concept and available tooling.
- [ ] Build a working application for the selected platform.
- [ ] Test remote navigation, focus visibility, back behavior, and a complete core task.
- [ ] Demonstrate the project functioning on the required device or accepted simulator/emulator.
- [ ] Record the target environment and reproducible setup/run instructions.
- [ ] Document which functionality works, which is simulated, and material limitations.

The official rules require a demo-ready Fire TV app on Fire OS or Vega OS. They specify showing the app on an actual Fire TV device or Fire TV/Vega simulator; the FAQs also describe emulator options. A browser-only demonstration does not establish this requirement on its own.

## Repository and submission materials

- [ ] Supply source code, required assets, and clear setup/run instructions.
- [ ] Select the original code's license before using the public/open-source submission route.
- [ ] Preserve third-party attribution and appropriate reuse terms.
- [ ] Provide a concise description of the product, user problem, features, and functionality.
- [ ] Prepare a public English demo video under three minutes on YouTube or Vimeo.
- [ ] Include product feedback on the tools, APIs, and SDKs used.
- [ ] Recheck the final Devpost submission fields against current official rules.

The repository is currently public. The rules allow a public repository with an open-source license, or a private repository shared with the specified reviewers. No visibility changes or reviewer invitations have been made.
